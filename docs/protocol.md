# Контракт кадра SmartMatrix

## Ответ модели

Консольный клиент (или сама ESP в режиме рисования из браузера) отправляет запрос в `POST <base-url>/chat/completions` без стриминга. Текст из `choices[0].message.content` должен быть JSON-объектом с единственным полем `rows`: массивом ровно из 16 строк, в каждой из которых ровно 16 символов палитры. Один символ — один пиксель. Пробелы внутри строк, неизвестные символы (включая строчные буквы), Markdown, лишние поля и кадры неверного размера не принимаются.

Системный промпт просит модель сначала выбрать отличительные детали и цвета объекта, затем сделать их заметными на сетке 16×16. Если детали не помещаются, модель должна упростить рисунок или показать объект крупнее, а не заменять его значком. Клиент проверяет формат кадра, но не его смысловое соответствие запросу.

| Символ | Цвет | RGB |
|:---:|:---|:---|
| `.` | Чёрный (выключен) | `0, 0, 0` |
| `W` | Белый | `255, 255, 255` |
| `R` | Красный | `255, 0, 0` |
| `O` | Оранжевый | `255, 128, 0` |
| `Y` | Жёлтый | `255, 255, 0` |
| `G` | Зелёный | `0, 255, 0` |
| `C` | Голубой | `0, 255, 255` |
| `B` | Синий | `0, 0, 255` |
| `P` | Фиолетовый | `160, 0, 255` |
| `M` | Пурпурный | `255, 0, 255` |
| `S` | Светлый телесный | `255, 204, 153` |
| `N` | Коричневый | `160, 82, 45` |
| `A` | Серый | `128, 128, 128` |
| `D` | Тёмно-серый | `64, 64, 64` |

Клиент показывает символьное превью, количество пикселей, отличных от чёрного, и максимум по всем каналам RGB до коррекции яркости на плате. Все точки `.` означают полностью чёрный кадр: клиент предупреждает об этом, но по-прежнему отправляет кадр.

| Индекс | Координаты `(x, y)` |
|---:|:---|
| 0 | `(0, 0)` |
| 15 | `(15, 0)` |
| 16 | `(0, 1)` |
| 255 | `(15, 15)` |

Логический порядок — слева направо в каждой строке, строки сверху вниз. Только прошивка преобразует логические координаты в физический порядок «змейкой».

## Передача на NodeMCU (ESP8266)

Клиент отправляет `POST http://<IPv4 платы>/frame` на порт `80`. Заголовки: `Content-Type: application/octet-stream` (без параметров), `Content-Length: 768`. Тело без заголовка кадра, разделителей и кодирования: 256 троек байт `R`, `G`, `B` в том же логическом порядке, что и в JSON. Байты первого пикселя имеют смещения `0`–`2`, последнего — `765`–`767`. `Transfer-Encoding`, сжатие тела и `Expect: 100-continue` не поддерживаются. Плата принимает один запрос на соединение и закрывает его после ответа.

Плата считывает весь кадр до обновления светодиодов. Ошибочный или оборванный приём не меняет предыдущий кадр:

| Код | Что означает |
|:---|:---|
| `204 No Content` | Кадр принят и выведен. Только этот код считается подтверждением. |
| `400 Bad Request` | Неверный формат запроса, длина тела или способ передачи. |
| `404 Not Found` / `405 Method Not Allowed` | Неверный путь или метод. |
| `408 Request Timeout` | Запрос не получен целиком за 5 секунд после принятия соединения. При обрыве соединения ответа может не быть. |
| `415 Unsupported Media Type` | Другой или отсутствующий тип тела либо неподдерживаемое кодирование. |
| `417 Expectation Failed` | Заголовок `Expect` не поддерживается. |
| `431 Request Header Fields Too Large` | Стартовая строка и заголовки превышают 1024 байта. |

Эндпоинт `/frame` не принимает API-ключ, промпт или JSON модели. Приёмник рассчитан на доверенную локальную сеть: HTTP без TLS и аутентификации, поэтому не открывайте порт платы в интернет.

## Рисование из браузера

Доступно по IPv4 платы после `Wi-Fi ready`, только через домашнюю сеть. На точке настройки `GET /` по-прежнему перенаправляет на `/wifi`. Браузер обращается только к плате, а плата — к API провайдера.

| Запрос | Вход и результат |
|:---|:---|
| `GET /`, `GET /draw.js` | Страница рисования и её скрипт. |
| `GET /api/config` | `200` с `{"configured":true}` или `{"configured":false}`. Никакие значения настроек не возвращаются. |
| `POST /api/config` | JSON `{"baseUrl":"…","model":"…","apiKey":"…","ca":"…","insecureTls":false}`. `apiKey`, `ca` и `insecureTls` необязательны. `204` означает, что настройки заменены в RAM; запрос к провайдеру ещё не выполнялся. Пустой или отсутствующий ключ удаляет прежний. |
| `POST /api/draw` | JSON `{"prompt":"…"}`. `200` означает, что кадр выведен; тело — `{"rgb":"…","lit":N}`. Строка `rgb` содержит 1536 строчных шестнадцатеричных символов (768 RGB-байт в порядке `/frame`), `lit` — число ненулевых пикселей. |

Для веб-маршрутов нужен `Host` с IPv4 платы (допускается `:80`); для POST также нужен `Origin: http://<IPv4 платы>`, `Content-Type: application/json` и обязательный `Content-Length`. Сжатие и `Transfer-Encoding` входящих запросов не поддерживаются. Лимит тела: 6144 байта для настроек и 4800 байт для рисования. Поля ограничены по длине в байтах: URL 240, ID модели 128, ключ 512, PEM 4096, промпт 768 в UTF-8. URL поддерживает имя хоста или IPv4 и необязательный порт, без логина, пароля, параметров и фрагмента.

Ошибки формы или заголовков возвращают `400` или `415`, незаданные настройки — `409`, ошибка связи, TLS или невалидный ответ провайдера — `502`, нехватка ресурсов или ещё не синхронизированные часы — `503`, тайм-аут провайдера — `504`. Ошибки обработки могут содержать текст для пользователя, но не секреты или сырой ответ API. При ошибке генерации матрица не меняется. Плата обрабатывает один запрос за раз; при ожидании модели другие запросы к плате тоже могут ждать.

Плата использует схему URL: HTTP или HTTPS (TLS 1.2, без перехода на HTTP). Для HTTPS по умолчанию проверяются сертификат и имя хоста; можно задать собственный корневой CA в PEM вместо встроенных. Если для HTTPS передано `insecureTls: true`, сертификат и имя хоста не проверяются и синхронизация часов не требуется. Этот тестовый режим несовместим с непустым `ca` и не защищает от подмены провайдера.

Переадресации провайдера не выполняются. Плата разбирает ответ API по мере чтения, не сохраняя всё тело. Поддерживаются `Content-Length`, `Transfer-Encoding: chunked` и тело до закрытия соединения. Сжатие не поддерживается. Лимит тела после удаления chunked-обрамления — 8192 байта; строка с размером chunk — до 128 байт, трейлеры суммарно — до 1024 байт. Чтение тела ограничено 30 секундами после получения заголовков. Кадр выводится только после чтения тела целиком. API-ключ не сохраняется на диск, но первоначально приходит от браузера по незашифрованному HTTP.

## Настройка Wi-Fi

Точка `SmartMatrix-XXXX` поднимается при каждом запуске. Её пароль — `SmartMatrix`, адрес настройки — `http://192.168.4.1/wifi`. При попытке подключения точка остаётся включённой; ESP8266 использует один радиоканал, поэтому при смене канала браузеру может потребоваться переподключение.

| Запрос | Через точку настройки | Через домашнюю сеть |
|:---|:---|:---|
| `GET /` | `303 See Other` на `/wifi`. | Страница рисования после завершения настройки. |
| `GET /wifi` | `200 OK`: HTML-форма, прогресс, результат или ошибка. После DHCP показывает IPv4 платы в домашней сети. | `200 OK`: HTML-статус подключения и IPv4 без формы и пароля. |
| `POST /wifi` | `303 See Other` на `/wifi`, если попытка принята. `400` для неверной формы, `409 Conflict`, если уже идёт подключение или завершается настройка. | `403 Forbidden`: менять настройки через домашнюю сеть нельзя. |
| `POST /frame` | `404 Not Found` до завершения настройки. | Принимает кадры в обычном режиме после отключения точки настройки. |

Форма отправляет `application/x-www-form-urlencoded` с обязательным `Content-Length` (до 384 байт). Поля: `ssid` (1–32 байта), `password` (пустой для открытой сети, 8–63 печатных ASCII-символа для WPA/WPA2 или 64 шестнадцатеричных цифры) и `token` (скрытое поле из формы). Для формы нужен `Host: 192.168.4.1` (допускается `:80`). Сеть считается настроенной только после получения IPv4 по DHCP. Пароль не возвращается в ответах и не печатается в логах.
