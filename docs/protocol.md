# Контракт кадра SmartMatrix

## Ответ модели

Клиент отправляет запрос в `POST <base-url>/chat/completions` без стриминга. Текст из `choices[0].message.content` должен быть JSON-объектом с единственным полем `rows`: массивом ровно из 16 строк, в каждой из которых ровно 16 символов палитры. Один символ — один пиксель. Пробелы внутри строк, неизвестные символы (включая строчные буквы), Markdown, лишние поля и кадры неверного размера не принимаются.

Системный промпт просит модель сначала выбрать отличительные детали и цвета объекта, затем сделать их заметными на сетке 16×16. Если детали не помещаются, модель должна упростить рисунок или показать объект крупнее, а не заменять его значком. Клиент проверяет формат кадра, но не его смысловое соответствие запросу.

| Символ | Цвет | RGB |
|:---:|:---|:---|
| `.` | Чёрный (выключен) | `0, 0, 0` |
| `W` | Белый | `255, 255, 255` |
| `R` | Красный | `255, 0, 0` |
| `O` | Оранжевый | `255, 128, 0` |
| `Y` | Жёлтый | `255, 255, 0` |
| `G` | Зелёный | `0, 255, 0` |
| `C` | Голубой | `0, 255, 255` |
| `B` | Синий | `0, 0, 255` |
| `P` | Фиолетовый | `160, 0, 255` |
| `M` | Пурпурный | `255, 0, 255` |
| `S` | Светлый телесный | `255, 204, 153` |
| `N` | Коричневый | `160, 82, 45` |
| `A` | Серый | `128, 128, 128` |
| `D` | Тёмно-серый | `64, 64, 64` |

Клиент показывает символьное превью, количество пикселей, отличных от чёрного, и максимум по всем каналам RGB до коррекции яркости на плате. Все точки `.` означают полностью чёрный кадр: клиент предупреждает об этом, но по-прежнему отправляет кадр.

| Индекс | Координаты `(x, y)` |
|---:|:---|
| 0 | `(0, 0)` |
| 15 | `(15, 0)` |
| 16 | `(0, 1)` |
| 255 | `(15, 15)` |

Логический порядок — слева направо в каждой строке, строки сверху вниз. Только прошивка преобразует логические координаты в физический порядок «змейкой».

## Передача на NodeMCU (ESP8266)

Клиент отправляет `POST http://<IPv4 платы>/frame` на порт `80`. Заголовки: `Content-Type: application/octet-stream` (без параметров), `Content-Length: 768`. Тело без заголовка кадра, разделителей и кодирования: 256 троек байт `R`, `G`, `B` в том же логическом порядке, что и в JSON. Байты первого пикселя имеют смещения `0`–`2`, последнего — `765`–`767`. `Transfer-Encoding`, сжатие тела и `Expect: 100-continue` не поддерживаются. Плата принимает один запрос на соединение и закрывает его после ответа.

Плата считывает весь кадр до обновления светодиодов. Ошибочный или оборванный приём не меняет предыдущий кадр:

| Код | Что означает |
|:---|:---|
| `204 No Content` | Кадр принят и выведен. Только этот код считается подтверждением. |
| `400 Bad Request` | Неверный формат запроса, длина тела или способ передачи. |
| `404 Not Found` / `405 Method Not Allowed` | Неверный путь или метод. |
| `408 Request Timeout` | Запрос не получен целиком за 5 секунд после принятия соединения. При обрыве соединения ответа может не быть. |
| `415 Unsupported Media Type` | Другой или отсутствующий тип тела либо неподдерживаемое кодирование. |
| `417 Expectation Failed` | Заголовок `Expect` не поддерживается. |
| `431 Request Header Fields Too Large` | Стартовая строка и заголовки превышают 1024 байта. |

На NodeMCU не передаются API-ключ, промпт или JSON модели. Приёмник рассчитан на доверенную локальную сеть: HTTP без TLS и аутентификации, поэтому не открывайте порт платы в интернет.
