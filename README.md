# SmartMatrix

SmartMatrix превращает текстовый запрос в статичный кадр 16×16 через OpenAI-совместимый API. NodeMCU 1.0 (ESP8266) подключается к Wi-Fi, получает IPv4 по DHCP и выводит кадр на матрицу WS2812B со «змейкой». Рисовать можно со страницы самой платы или через консольный клиент .NET 8.

## Рисование из браузера

1. Прошейте плату и настройте Wi-Fi по инструкции ниже. Подключите телефон или компьютер к той же домашней сети и дождитесь `Wi-Fi ready` в Serial Monitor.
2. Откройте **`http://<IPv4 платы>/`**. В настройках введите базовый URL OpenAI-совместимого API (например, `https://api.openai.com/v1`), ID модели и, если требуется, API-ключ. Нажмите «Сохранить настройки».
3. Введите промпт и нажмите «Нарисовать». ESP сама обращается к провайдеру и выводит корректный кадр. Страница показывает цветное превью и число ненулевых пикселей. При ошибке предыдущий рисунок остаётся на матрице.

Компьютер с .NET для этого не нужен. Настройки API хранятся на плате только до перезагрузки, ключ не возвращается и не отправляется браузером с каждым промптом. **Страница платы использует HTTP без аутентификации:** любой участник этой локальной сети может менять настройки и запускать генерацию; ввод ключа не шифруется. Используйте только доверенную сеть, не открывайте порт платы в интернет.

- Адрес `http://…` подходит для локального API. Если передать ключ такому провайдеру, он не будет зашифрован и на участке ESP → провайдер.
- Для `https://…` плата проверяет имя хоста и цепочку сертификатов по TLS 1.2. Нужен доступ к NTP; если часы ещё не синхронизировались, повторите запрос немного позже. Встроены корневые CA GTS Root R4, ISRG Root X1 и DigiCert Global Root G2. Для другой цепочки вставьте корневой CA провайдера в формате PEM. При ошибке TLS плата не переключается на HTTP.
- Для тестового HTTPS-провайдера можно включить **«Не проверять сертификат HTTPS»** и заново сохранить настройки. ESP продолжит использовать TLS 1.2, но не будет проверять сертификат и имя хоста; PEM и синхронизация часов для этого режима не нужны. Используйте его только для тестов: без проверки возможна подмена провайдера и перехват ключа.
- Совместимость HTTPS с конкретным провайдером зависит от поддержки TLS 1.2 и доступной памяти ESP8266. Выбирайте модель, способную вернуть короткий JSON-кадр без стриминга.

## Консольный клиент

```powershell
dotnet build SmartMatrix.sln
dotnet run --project src/SmartMatrix.Cli
```

1. Введите базовый URL API, например `https://api.openai.com/v1`, и ключ. Клиент добавляет к URL `models` и `chat/completions`, поэтому путь API (например, `/v1`) нужно включить в адрес. Ключ при интерактивном вводе не отображается; клиент не сохраняет его.
2. Выберите модель по номеру. Если список пуст или недоступен, введите ID модели вручную. При HTTP 401 или 403 клиент сообщает об ошибке доступа.
3. Введите IPv4 платы из Serial Monitor.
4. Вводите промпты по одному на строку. Модель рисует символами [фиксированной палитры](docs/protocol.md#ответ-модели), а клиент преобразует рисунок в RGB. Перед отправкой клиент показывает превью 16×16, число ненулевых пикселей и максимальное значение RGB. Чёрный кадр сопровождается предупреждением, но отправляется: он может быть нужен, чтобы погасить матрицу. Успех показывается только после подтверждения платы.
5. Нажмите Enter на пустой строке, чтобы выйти. Ошибка одного кадра не мешает ввести следующий; невалидный кадр не отправляется. При выходе код `0` означает, что ошибок не было, а код `1` — что произошла ошибка.

Тесты клиента без сети и платы:

```powershell
dotnet run --project tests/SmartMatrix.Tests
```

## Прошивка NodeMCU 1.0 (ESP8266)

1. В Arduino IDE установите пакет **esp8266 by ESP8266 Community** и библиотеки **FastLED** и **ArduinoJson 7**. Если пакета нет в менеджере плат, добавьте в настройки Arduino IDE [URL пакета ESP8266](https://arduino.esp8266.com/stable/package_esp8266com_index.json). Выберите плату **NodeMCU 1.0 (ESP-12E Module)** и её COM-порт.
2. Откройте `firmware/SmartMatrix/SmartMatrix.ino`. По умолчанию `DIN` матрицы подключается к **D5 (GPIO14)**. Если используете другой вывод, задайте его в `DataPin`. Настройте `FirstPixel` под физический стартовый угол. Код поддерживает горизонтальную «змейку». Файл `secrets.h` больше не нужен.
3. Для проверки углов выставьте `ShowStartupTest = true`. Верхний левый угол должен быть красным, верхний правый — зелёным, нижний левый — синим, нижний правый — белым.
4. Загрузите скетч и откройте Serial Monitor на `115200`. Подключите телефон или компьютер к сети **`SmartMatrix-XXXX`** (имя платы видно в Serial Monitor), пароль **`SmartMatrix`**. Если устройство предупредит об отсутствии интернета, останьтесь в этой сети.
5. В браузере откройте **`http://192.168.4.1/wifi`**, введите имя и пароль домашней сети **2,4 ГГц** и нажмите **Connect**. Для открытой сети оставьте пароль пустым. При ошибке или отсутствии IP через 30 секунд точка настройки останется доступной и можно будет повторить попытку. При переключении радиоканала телефон может временно отключиться от точки: подключитесь к ней снова или проверьте Serial Monitor.
6. При успехе возьмите адрес `NodeMCU IPv4: …` со страницы или из Serial Monitor. Примерно через 20 секунд после получения IP плата отключит точку настройки и начнёт принимать кадры. Верните телефон или компьютер в домашнюю сеть и откройте `http://<IP платы>/` для рисования или `/wifi` для проверки статуса. Этот же IP можно ввести в консольном клиенте.

ESP сохраняет настройки во флеш-памяти только после получения IP. При перезапуске точка настройки всегда поднимается первой: если настройки уже есть, у вас есть 30 секунд, чтобы отправить новые через форму, прежде чем плата попробует подключиться к сохранённой сети. Неудачная попытка не заменяет сохранённые настройки. Если стартовый вывод пропущен или нужно снова открыть окно настройки, перезагрузите плату с открытым Serial Monitor.

Пароль точки настройки фиксированный и известен. Настраивайте плату в доверенном окружении: форма использует HTTP без TLS, а настройки хранятся во флеш-памяти без шифрования.

### Если плата не получает IP

- `Wi-Fi: still waiting for association` — плата ещё не подключилась к точке. Код `201` означает, что точка не найдена; `202` — сбой аутентификации; `15` или `204` — истекло время согласования защиты. Проверьте диапазон 2,4 ГГц, SSID, пароль и режим WPA2.
- `Wi-Fi: associated, ... waiting for DHCP`, но без `NodeMCU IPv4: ...` — плата подключилась к точке, но ещё не получила IP. Проверьте DHCP на роутере.

Во время попытки подключения плата печатает статус каждые 5 секунд. Имя и пароль домашней сети в журнал не выводятся.

### Проверка настройки на плате

1. Введите неверный пароль или имя несуществующей сети. Дождитесь ошибки, затем отправьте верные данные, не перезагружая плату.
2. Убедитесь, что после выключения точки настройки `GET /wifi` по новому IP показывает статус без формы. Из домашней сети `curl.exe -i -X POST http://<IP платы>/wifi` должен вернуть `403 Forbidden` (подставьте IP платы, не передавайте пароль).
3. Перезапустите плату и ничего не вводите: она должна подключиться с сохранёнными настройками. Если сеть недоступна, форма должна остаться доступной после ошибки.

## Проверка по сети без API

Подключите компьютер и NodeMCU к одной локальной сети. Для этой проверки удобно оставить `ShowStartupTest = false`, чтобы до отправки матрица была выключена.

```powershell
dotnet run --project src/SmartMatrix.Cli -- --test-frame
```

Введите IP из Serial Monitor. После подтверждения платы проверьте четыре угла: красный вверху слева, зелёный вверху справа, синий внизу слева и белый внизу справа. Остальные пиксели выключены.

Чтобы проверить, что неверный пакет не меняет изображение, отправьте один байт вместо 768 (замените IP на адрес своей платы):

```powershell
curl.exe -i -H "Content-Type: application/octet-stream" --data-binary "x" http://192.168.1.42/frame
```

Плата должна вернуть `400 Bad Request`, а предыдущий кадр — остаться на матрице.

## Проверки прошивки без платы

Проверка раскладки, формата кадра, настроек Wi-Fi, границы локальных HTTP-заголовков и потокового разбора ответа модели (нужен компилятор C++17; подходит `xtensa-lx106-elf-g++` из пакета ESP8266):

```powershell
$tests = Get-ChildItem tests/firmware/*Tests.cpp | ForEach-Object FullName
g++ -std=c++17 -fsyntax-only @tests
node --test tests/firmware/DrawPageTests.cjs
```

Сборка прошивки через Arduino CLI:

```powershell
arduino-cli lib install ArduinoJson
arduino-cli compile --fqbn esp8266:esp8266:nodemcuv2 firmware/SmartMatrix
```

Проверка на плате: сохраните настройки, отправьте два промпта без повторного ввода ключа и сравните превью с матрицей. Для HTTPS отдельно проверьте успешный запрос и отказ при указании недоверенного CA. Проверьте, что после перезагрузки страница снова предлагает ввести настройки.
